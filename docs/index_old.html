Installation & quick start

UI Kit ships as a single CSS file plus an HTML pattern library. Drop the stylesheet in, copy the markup for any component, and theme by overriding the CSS custom properties at :root.

1. Install

npm install @ui-kit/ui
# or via CDN
<link rel="stylesheet" href="https://unpkg.com/@ui-kit/ui@3/dist/ui-kit.min.css" />

2. Use a component

<button class="btn btn--brand">Get started</button>
<input class="input" placeholder="Search..." />
<span class="badge badge--success">Active</span>

3. Theme

Override the brand and accent ramps at :root. Every component cascades from these tokens — no component-level overrides required.

:root {
  --color-brand-500: #0197f6;   /* your brand */
  --color-brand-600: #0177c4;
  --color-accent-500: #d7263d;  /* your accent */
}

Principles

Design with intent

Six guiding principles. Every token, component, and layout decision should serve at least one of them.

Vibrant, but disciplined

Bold color is a tool — wielded carefully. Saturate the moments that matter; let the rest breathe.

Tokens, not magic numbers

Every value is a named decision. Theme the entire system by overriding the token layer alone.

Motion clarifies causality

Transitions tell users what came from where. Three durations, one easing curve, never decoration for its own sake.

Accessible by default

Every color pair clears WCAG AA. Every interactive surface has visible focus. Motion respects user preference.

Composable, not coupled

Small, single-purpose, theme-blind components. They compose into patterns; patterns into products.

Delight in the details

A confident gradient. A satisfying spring. A glow that earns its place. Restraint everywhere — except the moments that matter.

Focus management

Visible focus is non-negotiable
Every interactive component renders a 2px brand-tinted ring on :focus-visible. Never remove the focus ring without providing an alternative; sighted keyboard users depend on it.
  • Modals and drawers trap focus until dismissed.
  • On open, focus moves to the first interactive element inside.
  • On close, focus returns to the trigger that opened the surface.
  • Pages and routes restore focus to the document body.

Reduced motion

All transitions honor prefers-reduced-motion: reduce. Decorative animations are removed; functional transitions (focus rings, state changes) are preserved but instant.

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}

Screen reader support

  • Icon-only buttons require aria-label describing the action.
  • Form fields require an explicit <label>; placeholder alone is insufficient.
  • Status messages (toasts, alerts) use role="status" or role="alert".
  • Loading states announce with aria-busy="true".
  • Decorative icons use aria-hidden="true" to avoid double-reading.

Base components

Button

A button triggers an action — submitting a form, opening a dialog, navigating, or initiating an async task. Reach for a button when the user is making a choice; reach for a link when they're moving between pages.

Anatomy

leading icon (optional) → ← label

Variants

Eight visual variants, ordered by visual weight. Use at most one filled (brand/accent/primary/danger/success) per view to maintain a clear primary action.

Sizes

Four sizes. Default (36px) aligns with input height — the baseline for forms and toolbars. Small (28px) for dense surfaces, Large (40px) for primary page actions, XL (48px) for hero CTAs.

States

Every interactive button moves through five states. Always preserve the focus ring; rely on hover for affordance, active for feedback, disabled for unavailability, loading for async work.

A11y checklist
Use a real <button> element — never a styled <div>. Icon-only buttons require aria-label. For async actions, set aria-busy="true" while loading. Disabled buttons remain keyboard-focusable when using aria-disabled instead of the disabled attribute, so screen readers can still announce them.

Code

<!-- Default -->
<button class="btn btn--brand">Get started</button>

<!-- With leading icon -->
<button class="btn btn--brand">
  <svg class="icon"><use href="#i-plus"/></svg> Add item
</button>

<!-- Icon-only (always include aria-label) -->
<button class="btn btn--secondary btn--icon" aria-label="Settings">
  <svg class="icon"><use href="#i-settings"/></svg>
</button>

<!-- Loading -->
<button class="btn btn--brand btn-loading" aria-busy="true">Saving</button>

Guidelines

Do
Lead with one primary (brand/accent/danger/success) action per view. Make it the most visually weighted element on screen.
Don't
Stack two filled buttons side by side. The user shouldn't weigh which call-to-action is the “real” one.
Do
Match button height to input height (36px default) when buttons sit alongside form fields.
Don't
Use button to navigate between pages — that's a job for <a>. Buttons trigger actions; links go places.

Practice

Guidelines

Patterns to internalize, traps to avoid. When in doubt, choose the option that produces a calmer, more predictable interface.

Do
Lead with one primary action per view. Make it the most visually weighted element on screen.
Don't
Stack two filled buttons side by side. The user shouldn't weigh which call-to-action is the “real” one.
Do
Use neutral text on neutral surfaces. Reserve brand color for interactive accents and key emphasis.
Don't
Color body text in brand. It reads as a link and quickly fatigues the eye over a long page.
Do
Use gradients for hero moments — usually one per view. They pull the eye where you want it.
Don't
Cover an entire page in gradient. Vibrant works because it contrasts with quiet — both have to exist.
Do
Reach for spacing tokens before inventing a new gap. The grid is the consistency.
Don't
Hard-code 17px, 22px, or other off-grid values. They compound into visual noise.
Do
Animate to clarify causality — what came from where, what changed, where focus moved.
Don't
Animate for delight at the cost of performance or accessibility. Honor reduced-motion preferences.
